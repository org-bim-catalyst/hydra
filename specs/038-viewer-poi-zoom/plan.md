# Implementation Plan: POI Viewer Zoom & Focus

**Branch**: `038-viewer-poi-zoom` | **Date**: 2026-08-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/038-viewer-poi-zoom/spec.md`

---

## Summary

When a user names a location in chat, the viewer must automatically zoom to an altitude that makes that place clearly visible and place a visual 3D marker at the resolved coordinates. Explicit zoom commands ("zoom in", "pull back", etc.) are detected via keyword matching and executed as live viewer camera commands. The backend extends `ConfirmedLocationData` to carry the geocoding viewport bounding box and `location_type`, which the frontend uses to drive accurate zoom. Display names use the user's original query, not the geocoding formatted address.

## Technical Context

**Language/Version**: C# (.NET 10), TypeScript (React 18 / Vite)

**Primary Dependencies**:
- Backend: ASP.NET Core, MediatR, System.Text.Json, Google Maps Geocoding API (existing)
- Frontend: React, Zustand, Three.js, Google Maps JavaScript SDK (`@googlemaps/js-api-loader`), `WebglOverlayView`

**Storage**: No new DB tables. `MarkerStyle` in `localStorage`.

**Testing**: `dotnet test` (xUnit) for backend; Vitest for frontend; `tsc -b --noEmit` for TS types.

**Target Platform**: Web (desktop + responsive mobile) — same as existing viewer.

**Project Type**: Feature extension on existing ASP.NET Core + React web application.

**Performance Goals**: Zoom animation completes within 1.5 s (SC-005); POI marker visible within 500 ms of zoom animation completing (SC-006).

**Constraints**: Must not break existing `zoomToLocation(lat, lng, zoom)` callers. All `localStorage` access must be try/catch-guarded. No new AI provider calls for zoom detection. `dotnet format` must pass (CRLF, no aligned switch arms).

**Scale/Scope**: Single-user viewer feature; no multi-user or server-side state.

## Phase 0: Research

Output in [research.md](research.md). Key decisions:

1. Viewport from Google Maps Geocoding API `geometry.viewport` — no extra API call.
2. Viewport flows as-is through all layers; viewer derives altitude from its own pixel dimensions.
3. `location_type` fallback altitudes: ROOFTOP/RANGE_INTERPOLATED 200 m, GEOMETRIC_CENTER 800 m, APPROXIMATE 8 000 m.
4. `LocationName` = user's query string, not `formatted_address`.
5. Zoom commands detected by keyword matching (no AI call).
6. POI marker via Google Maps `WebglOverlayView` + Three.js scene graph.
7. `MarkerStyle` persisted in `localStorage` via Zustand store.
8. Viewer engine: new `fitBounds` and `zoomBy` methods; no change to existing `zoomToLocation`.
9. `ChatStreamChunk` gets `ViewerZoomCommand? ViewerZoom`; `AiController` emits `__ZOOM__{direction}`.
10. All changes follow Clean Architecture; no constitution violations.
